## Local GPU access (verified 2026-10-14)

The RTX 3080 Laptop GPU has 16 GiB VRAM and a working NVIDIA 560.35.05
driver. The default execution sandbox hides `/dev/nvidia*`: `nvidia-smi`
fails there even though the host GPU works. Do not infer missing hardware,
reinstall drivers, or spend a session debugging CUDA inside that sandbox.

- Run GPU commands through `exec_command` with
  `sandbox_permissions: "require_escalated"` and a justification explaining the
  local GPU experiment. The execution approval mechanism still applies; do not
  bypass it. A normal host terminal also exposes the GPU.
- First check `nvidia-smi` outside the sandbox, then check the selected Python's
  `torch.__version__`, `torch.version.cuda`, and `torch.cuda.is_available()`.
  The CPU benchmark environment `/tmp/c5r-predict` has **CPU-only PyTorch**;
  lifting sandbox restrictions alone does not make that build CUDA-capable.
- The separate working GPU environment is `/tmp/c5r-gpu` (Python 3.10.9,
  PyTorch 2.6.0+cu124, Transformers 4.49.0). Use its Python explicitly:
  `/tmp/c5r-gpu/bin/python code/experiments/accelerated/gpu_check.py`.
  This runs cached ESM-1v 650M in float32, checks CPU/GPU numerical agreement
  and repeated GPU inference, and records synchronized timing and peak VRAM in
  `notes/accelerated/gpu_verification.json` (generated, ignored).
- `/tmp` environments are disposable. Rebuild with `uv venv --python 3.10
  /tmp/c5r-gpu`, then `uv pip install --python /tmp/c5r-gpu/bin/python
  -r code/experiments/accelerated/requirements-gpu.txt
  --index https://download.pytorch.org/whl/cu124
  --index https://pypi.org/simple --index-strategy unsafe-best-match`.
  These mixed indexes resolve the pinned CUDA wheel and its pinned dependencies;
  use only these trusted indexes. Set `UV_CACHE_DIR=/tmp/c5r-uv-cache` if the
  default cache is unwritable. Use `/home/error/.local/bin/uv` if necessary.
  Model cache retrieval is documented in the accelerated experiment README;
  the smoke test intentionally uses `local_files_only=True`.
- Keep CPU measurements labelled CPU. Successful GPU execution establishes
  hardware/software feasibility, not functional prediction accuracy. Preserve
  the OmpF benchmark freeze; no GPU troubleshooting requires changing it.
- The sprint also verified **ESM-2 3B** (2,841,632,194 parameters) on this GPU:
  load with `torch_dtype=torch.float16`, `low_cpu_mem_usage=True`, and
  `device_map={"": "cuda"}`. The two upstream float32 weight shards total
  approximately 11.37 GB on disk; this is distinct from runtime VRAM. On BK's
  mutation-centred 1022-residue contexts, 247 masked sites took 295.4 seconds
  under shared load, peaking at 6,066 MiB allocated / 6,388 MiB reserved.
  `code/experiments/sprint/sequence.py --model esm2_3b --datasets bk` is the
  executable path; its pinned model revision is in
  `sources/sprint/esm2_3b_model.json`. Use `/tmp/c5r-gpu/bin/python`, the GPU
  execution permissions above, and `HF_HUB_DISABLE_XET=1` for retrieval.
  Avoid loading another copy while other experiments occupy the remaining VRAM.
- CUDA autocast is a verified inference optimization for ESM-1v 650M:
  `with torch.inference_mode(), torch.autocast("cuda", dtype=torch.float16):`.
  A paired batch2/1022-residue probe measured median 3.46s FP32 versus 1.83s
  autocast under shared load (1.9x); two conservative mutant-minus-WT feature
  vectors differed by 0.54%/0.81% in relative L2. The receipt is
  `notes/sprint/gpu_precision_probe.json`, generated by
  `code/experiments/sprint/external_bk_sequence.py`. This proves a useful local
  numerical/speed option, not unchanged functional rankings for every model.
  Keep precision explicit and preserve FP32 reference caches when comparing it.
